# 飞行试验检查单 · 双支离线修订复核

两支离线修订（各至多 80 条按序操作）同时回传后，复核员在浏览器中判断它们能否合为一份
可执行步骤表。核心是一套**保留删除锚点（墓碑）的序列模型 + 双支操作变换（OT）**：
所有修改以步骤的全局唯一 ASCII 标识寻址，不按下标落修改，避免位置漂移。

## 合并规则

- **插入**：带全局唯一的新步骤标识，可锚定在首位（`HEAD`）或任一**尚存、已删（墓碑）、
  本支先前插入**的步骤之后。
- **同锚点并发插入**：按 `(分支名, 操作标识)` 字典序稳定裁定，结论与左右录入顺序无关。
- **删除**：打墓碑，不摘除节点——后续插入仍可锚定其原位置。
- **替换**：以标识定位，与下标无关。
- **可合并**：两支（或同支）对同一步骤的相同替换；对同一步骤的重复删除。
- **必须拒绝**（展示首个冲突的双方操作及变换依据）：
  - 同一步骤上的不同并发替换；
  - 删除与替换交叉（含替换已删墓碑）；
  - 插入的新标识重复（撞基线 / 撞任一支插入）；
  - 悬空引用（锚点 / 目标不存在，或引用仅存在于对方分支的私有插入）。

通过时页面同时给出：**规范合并步骤表**、保留的墓碑清单、**每条原操作的保留 / 转换 / 合并
结果及依据**。输入一旦改变或校验失败，旧结论立即作废，不保留过期结果。

## 录入格式

```
# 基线：每行  标识: 文本
S1: 通电前外部检查
S2: 惯导初始对准

# 操作（OPID 为支内唯一操作标识）
a1 insert NA after S3: 左支替代试车检查     # 插入；锚点可用 HEAD / 首位
a2 delete S3                                # 删除（保留墓碑）
a3 replace S2: 惯导对准（修订）             # 文本替换
```

标识字符集：`A-Za-z0-9_.@-`。

## 运行

```bash
# 默认宿主端口 8080
docker compose up -d --build
open http://localhost:8080

# 自定义宿主端口
WEB_PORT=9090 docker compose up -d
```

健康检查：`GET /health` → `{"status":"ok","service":"flight-checklist-web"}`。

## 验收（verify 服务）

`verify` 服务等待 `web` 健康后运行：领域测试、构建检查（语法/资源/模型要点）、
页面与健康 HTTP 冒烟，随后退出并以状态码报告：

```bash
docker compose build
docker compose run --rm verify    # 全部通过退出码 0，任一失败非零
```

本地直接运行领域测试：

```bash
node tests/domain.test.js
```

## 结构

```
src/domain.js   墓碑序列模型与双支 OT（浏览器 / Node 共用的 UMD 模块，44 项领域测试）

src/app.js      页面逻辑（输入变更即作废旧结论）
tests/          零依赖领域测试
verify/         Compose verify 服务的验收脚本
nginx.conf      静态站点 + /health
```
